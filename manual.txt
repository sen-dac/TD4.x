//--------------------------------------------------------------------------------------------
// 概要
//--------------------------------------------------------------------------------------------

書籍『CPUの創りかた』では、IC 10個で作られる「TD4」と呼ばれる4bitCPUの設計とその解説を通じ、
CPU動作の基本原理を学べます。

本ソフトは、この「TD4」のエミュレータであり、アセンブラとしても機能します。

大きな特徴としては、TD4実機に"ありえないプログラム"を入力した際の挙動も再現しているところです。
(確認に使用したTD4実機の作成は、nucky氏が頒布されたPCB基板を利用させていただきました)

このような未定義動作は、通常の本ソフト上からのアセンブラによるプログラミングを行った場合は混入
することがありません。

ただし、バイナリエディタ等で意図的にマシン語を改変すれば再現可能です。
ご興味がある方は、一体どのような挙動をとるのか、ぜひ確認してみてください。

書籍『CPUの創りかた』がお手元にない場合でも、お楽しみいただけるよう配慮していますが、可能であれ
ば、ぜひ書籍もあわせてお読みいただくことをお勧めします。


//--------------------------------------------------------------------------------------------
// 動作環境
//--------------------------------------------------------------------------------------------

■ X68000 10MHz以上 メモリ2MB以上

X68000 CompactXVI (10MHz動作)にて動作確認済み。


■ Windows上で動作するX68000エミュレータ

XM6 TypeG version 3.36にて動作確認済み。


■ X68000 Z

PRODUCT EDITION BLACK MODEL(PE)
ファームウェア ver.1.7.3 にて動作確認済み。


//--------------------------------------------------------------------------------------------
// アプリケーションの起動と終了
//--------------------------------------------------------------------------------------------

Human68k上からTD4.xを起動してください。

例：
A:\>td4

起動時にロードするROM(TD4.x上で動作するプログラム)ファイルを指定することも可能です。
例として、サンプルでROMディレクトリに同梱されている「ラーメンタイマー」をロードする場合は以下の
ようにします。

例：
A:\>td4 ./rom/ramen_timer.tdx

※ 注：TD4公式エミュレータの.td4ファイルと、本ソフトのファイルには、互換性がありません。

Q コマンドを入力すると、アプリケーションが終了します。


//--------------------------------------------------------------------------------------------
// 実行環境毎のキャリブレーション (動作速度調整)
//--------------------------------------------------------------------------------------------

クロックモード 1Hz 動作時の速度が実行環境により微妙に異なります。
このため、実行環境毎にキャリブレーションが必要となります。

まず、必ず Clock が 1Hz になっていることを確認してください。
もし 10Hz になっていた場合は O (Oscillator) コマンドでクロックモードが切り替わります。

ラーメンタイマー(ramen_timer.tdx)を G コマンドで実行し、ブザー吹鳴までの時間が可能な限り3分15秒
に近付くように TD4.ini ファイルの WAIT 設定値を調整してください。

WAIT の値が大きいほど処理が遅くなります。

R コマンドで、TD4をリセットできます。

TD4.ini ファイルが読み込まれるのは、TD4.xの起動時のみとなります。
このため、TD4.ini ファイルを編集した場合は、TD4.xの再起動が必要です。


TD4.ini デフォルトの記述 (#以降改行までコメント扱い)：

# WAIT 47  # X68000 実機 用 (CompactXVI 10MHz にて確認)
WAIT   46  # X68000 Z / XM6 TypeG 用調整値


参考値として、本ソフト作者の環境では、以下の設定値で3分14秒となりました。
(これ以上は調整が不可能でしたが、ラーメンの味は変わりませんでした)

X68000 CompactXVI        → 設定値：47
XM6 TypeG (version 3.37) → 設定値：46
X68000 Z PE(ver.1.7.3)   → 設定値：46

※ 3分15秒は、書籍『CPUの創りかた』(P.298)に記載されている仕様上のラーメンタイマー実行時間です。


//--------------------------------------------------------------------------------------------
// コマンドリファレンス
//--------------------------------------------------------------------------------------------

各コマンドは大文字でも小文字でも入力可能です。
入力後、リターンキーの押下で実行されます。

G    : (Go) オートモード開始
       現在のプログラムカウンタの位置から連続してプログラムを実行します。
       ESCキーで停止してコマンド入力可能な状態に戻ります。

T    : (Trace) ステップ実行
       現在のプログラムカウンタが指す行の命令のみを実行します。

R    : (Reset) ターゲットCPU リセット
       A, Bレジスタ、INPUT, OUTPUT, Cフラグ、プログラムカウンタがリセットされます。
       ROM領域(実行プログラム)は保持されます。

O    : (Oscillator) ターゲットCPU 動作クロック変更(1Hz / 10Hz)
       オートモード実行時の動作クロックを切り替えます。
       1  Hz モード：キャリブレーションが正しく行われている場合、1Hzの近似値で動作します。
       10 Hz モード：単にノーウェイトで動作をするモードとなっており、速度を再現していません。

BS n : (BreakPoint Set) ブレークポイント設置 (n = 0～F)
       コマンド入力例(アドレス$Aでブレークさせたい場合)：
       BS A
       ※ BS の後の空白は必ず1つである必要があります。

BC n : (BreakPoint Clear n) ブレークポイント解除 (n = 0～F)
       コマンド入力例(アドレス$3のブレークポイントを解除したい場合)：
       BC 3
       ※ BC の後の空白は必ず1つである必要があります。

BC   : (BreakPoint Clear All) ブレークポイントを全て解除
       パラメータを設定せずにBCコマンドを実行した場合は全てのブレークポイントが解除されます。

N    : (Next) 現在行を実行せずにPCを1つ進める
       アセンブラ記述により、プログラミングを行う際に利用してください。

P    : (Prev) 現在行を実行せずにPCを1つ戻す
       アセンブラ記述により、プログラミングを行う際に利用してください。

S fn : (Save) プログラムをセーブ (fn = パス/ファイル名.拡張子)
       現在のROMの状態(プログラム)をファイルに保存します。
       コマンド入力例：
       S ./rom/tes.tdx

       ※1. S の後の空白は必ず1つである必要があります。
       ※2. TD4公式エミュレータのファイル(.td4)とは互換性がありません。

L fn : (Load) プログラムをロード (fn = パス/ファイル名.拡張子)
       ROMにファイルからプログラムを読み込みます。
       コマンド入力例：
       L ./rom/tes.tdx

       ※1. L の後の空白は必ず1つである必要があります。
       ※2. TD4公式エミュレータのファイル(.td4)とは互換性がありません。

0～F : (Input Val) INPUTに値を設定 (即時反映)
       $を付けずに、そのまま0～Fを入力してください。

Q    : (Quit) アプリケーション終了
       TD4.x を終了します。


//--------------------------------------------------------------------------------------------
// アセンブラ記述
//--------------------------------------------------------------------------------------------

コマンド入力欄に以下のアセンブラ記述を行うと、プログラムカウンタが現在指している行(アドレス)
の命令が書き変わります。

書籍『CPUの創りかた』では、Im値が2進数で表記されていますが、本ソフトでは16進数で記述します。
値の前には16進数であることを示す $ を書く必要があります。

命令(オペコード)と、パラメータ(オペランド)の間のスペースは必ず1つとしてください。
また、第1オペランドと第2オペランドの間は , で区切り、間には空白等を入れないでください。

プログラムを書き換えた場合は、忘れずに S コマンドでファイルの保存を行ってください。

大文字でも小文字でも入力が可能です。
入力後、リターンキーの押下でROMに書き込まれます。

この段階では、まだ当該命令は実行されません。

当該行にPCがある状態で T コマンドを実行するか、G コマンド実行中に当該行をPCが通過する際に実行
されます。


■ NOP        何もしない

命令の詳細 … 何もしません。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例 (何もしない)：

NOP

※ ADD A,$0 と記述した場合も、NOPとして扱われます。


■ MOV A,Im   AレジスタにImを転送

命令の詳細 … イミディエイトデータをAレジスタに転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例 (Aレジスタに値$Cを転送)：

MOV A,$C


■ MOV B,Im   BレジスタにImを転送

命令の詳細 … イミディエイトデータをBレジスタに転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例 (Bレジスタに値$6を転送)：

MOV B,$6


■ MOV A,B    AレジスタにBレジスタを転送

命令の詳細 … BレジスタをAレジスタに転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例 (BレジスタをAレジスタに転送)：

MOV A,B


■ MOV B,A    BレジスタにAレジスタを転送

命令の詳細 … AレジスタをBレジスタに転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例 (AレジスタをBレジスタに転送)：

MOV B,A


■ ADD A,Im   AレジスタにImを加算

命令の詳細 … イミディエイトデータをAレジスタに加算します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：キャリー発生時に1になります。
                      それ以外の場合は0になります。

記述例 (Aレジスタに値$1を加算)：

ADD A,$1


■ ADD B,Im   BレジスタにImを加算

命令の詳細 … イミディエイトデータをBレジスタに加算します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：キャリー発生時に1になります。
                      それ以外の場合は0になります。

記述例 (Bレジスタに値$Fを加算)：

ADD B,$F


■ IN  A      入力ポート(INPUT)からAレジスタへ転送

命令の詳細 … 入力ポート(INPUT)のデータをAレジスタへ転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例：

IN A


■ IN  B      入力ポート(INPUT)からBレジスタへ転送

命令の詳細 … 入力ポート(INPUT)のデータをBレジスタへ転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例：

IN B


■ OUT Im     出力ポート(OUTPUT)へImを転送

命令の詳細 … イミディエイトデータを出力ポート(OUTPUT)へ転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例  (OUTPUTに値$6を転送)：

OUT $6


■ OUT B     出力ポート(OUTPUT)へBレジスタを転送

命令の詳細 … Bレジスタを出力ポート(OUTPUT)へ転送します。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例：

OUT B


■ JMP Im     Im番地へジャンプ (無条件ジャンプ)

命令の詳細 … イミディエイトデータで示された番地へジャンプします。
Cフラグ    … 実行時：この命令はCフラグの影響を受けません。
              実行後：必ず0になります。

記述例 ($A番地へジャンプ)：

JMP $A


■ JNC Im     Im番地へジャンプ (Cフラグが0のときのみ)

命令の詳細 … Cフラグが0のときにイミディエイトデータで示された番地へジャンプします。
              Cフラグが1なら何もしません。
Cフラグ    … 実行時：この命令はCフラグにより動作が変わります。
              実行後：必ず0になります。

記述例 (Cフラグが0なら$0番地へジャンプ)：

JNC $0
